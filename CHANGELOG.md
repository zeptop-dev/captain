# Changelog

One entry per release tag, newest first, condensed from the commit subjects
between that tag and the previous one (`git log --format=%s <prev>..<tag>`).
Merge commits and formatting-only commits are left out. Binaries and
`SHA256SUMS` for every tag are on the GitHub Release; the in-app updater
installs them (Settings → Backups and maintenance → Version and updates).

- **v1.4.1** (2026-09-21) — installer: **IPv6 clients keep their real address in Docker mode.** Compose's default bridge network had no IPv6, so a v6 connection to the published 80/443 went through docker-proxy and Captain saw the bridge gateway (`172.x.0.1`) as the client — every v6 visitor became one address for the login rate limit, the admin allow-list and the connection log. When the host has a global IPv6 address the script now enables IPv6 on the network (a ULA subnet, `fd0c:a97a:1::/64`) and says so; Docker < 27 additionally needs `ip6tables` in daemon.json and the script tells you. New `--network host` for those who want no bridge at all: `network_mode: host`, Captain bound to the host directly, and behind a containerised proxy to that proxy network's gateway address, the one host address a bridge container can reach. Rerunning with a different network rewrites `config.yaml`'s `listen` (backup kept). Verified by dry-running the script against stubbed docker/ss/ip in five configurations.

- **v1.2.1** (2026-09-20) — an encrypted off-site backup now carries **`config.yaml` beside the database** (`captain-<date>.tar.gz.age`): the database has the accounts, the nodes and their token hashes, but `base_url` and the payment gateway keys live only in the config file, so a panel rebuilt from the database alone came up unable to take money. One file is now enough. The config is only ever included when encryption is on — it holds those keys in plain text — and an unencrypted remote copy stays the gzipped database it was. `captain backup open` unpacks either shape, prints every file it wrote and never overwrites an existing one. Verified by restoring from a real bucket into a fresh panel: a live node's own token authenticated against it, so a restored panel keeps its fleet as soon as DNS points at it (`docs/OPERATIONS.md`).
- **v1.2.0** (2026-09-19) —
  - **Encrypted off-site backups**: remote copies are sealed with [age](https://age-encryption.org) before upload (Settings → Database backups → Encrypt remote copies), because the database holds password hashes, TOTP secrets, payment keys, node secrets and every subscription token. *Public key* mode — the console generates a pair and shows the private key once; the panel keeps only the public half — lets Captain seal its copies but not open them; *passphrase* mode is simpler and protects the bucket rather than the host. Sealed copies are `captain-<date>.db.gz.age`, streamed in constant memory. `captain backup open` decrypts and unpacks a remote copy into a database file (`-identity key.txt` or `-passphrase-env VAR`); the standard `age` tool works too.

  - **Portal fixes** from a new portal test suite (1,500 lines; the customer API's coverage went from 66 % to 97 %, including every route refused without a session, cross-site, or for another user's data):
    - cancelling a queued plan refunded the *newest* paid order for the same plan, not the one that bought the row — queue 30 days for 10.00 and 90 days for 27.00, cancel the 30 and get 27.00 back. Subscriptions now record the order that bought them (migration 50) and only that order is refunded; a row without one (admin grant, gift code, a row from before this release) is cancelled without an automatic refund;
    - invite codes could be bound in a loop (A↔B), and with multi-level rewards the buyer earned commission on their own order; the bind is refused and the commission walk stops at the buyer or at anyone already paid;
    - a balance payment refused for insufficient funds left a pending order holding the coupon use, so the retry after a top-up failed with "coupon already used"; the unpaid order is now discarded;
    - Telegram operator notices put ticket subjects, withdrawal method and account and email addresses into HTML unescaped; they are escaped;
    - the password reset answered differently for unknown, staff and known addresses; every failure now gets the same answer, and no code mail goes to staff addresses;
    - store errors no longer reach customers (logged, answered "internal error"), deleting an unknown device answers 404, logout requires the same origin, a client address may request at most 10 code mails an hour, withdrawal method and account are length-capped, and the reading language is kept for staff accounts too.
  - **Port forwards with several targets** (bosun ≥ 0.49): a backup line for when the first is down, or more lines to spread connections over — *failover* (first healthy target; a failed dial moves on before the client notices) or *weighted round-robin*; realm offers round-robin only, nft keeps one target. Each target's health, RTT and connections show next to the rule (`forward_status.targets_json`, migration 49).
- **v1.1.1** (2026-09-19) — security toolchain release, no feature change. The release binaries were compiled with **Go 1.26.0** — setup-go v5 installed the `go` directive's version literally — so they missed the standard-library fixes of 1.26.1–1.26.8 (crypto/tls post-handshake message limits, net/http's unencrypted HTTP/2 check ignoring ReadHeaderTimeout, html/template escaping, encoding/asn1 and encoding/xml recursion, crypto/x509 hostname parsing, net/url and mime quadratic cases). `go.mod` now carries `toolchain go1.26.8`, which setup-go v6 installs, and the Docker build image is pinned to the same patch release (the images were already built with a current 1.26). CI: `govulncheck` gates every push and tag and runs weekly; Dependabot opens grouped weekly updates. Pairs with bosun v0.48.1, whose cores are rebuilt with the same toolchain.

- **v0.58.2** (2026-09-17) — a node that restarts begins a new report-batch series, and the panel now charges it: a batch is applied when its number is ahead of the last one or so far behind that the agent must have restarted with a fresh series, and dropped in between (a re-send carries the previous number, and a copy delayed past the following batch must not be billed twice). Before this, a restarted agent's traffic was thrown away until its counter climbed back past the old number. The numbering itself arrived in v0.58.0; bosun v0.46.1 seeds the counter from the clock, so a restart moves it forward. Console: the dynamic speed limit's "also throttle users with no speed limit" switch is visible, with what it costs (those users have no shaper yet, so applying and lifting a throttle reloads the cores serving them).
- **v0.58.1** (2026-09-17) — follow-ups to v0.58.0 found while re-reading the batch: a settings document that is a *list* (the subscription response rules) is replaced again, not merged — decoding a shorter array onto the stored one let a rule keep fields from whatever used to sit in its place; a per-user device limit above 64 wins over the storage ceiling, so an operator who allows 100 devices gets 100.
- **v0.58.0** (2026-09-17) — cold-review fix batch, nothing to configure unless noted:
  - **Release gating**: `release.yml` now runs the same checks as CI (i18n parity, oxlint, gofmt, vet, `go test -race`) and the image job waits for the binaries, so a red commit cannot be released; README documents the release rules (never move a published tag, `make e2e` before a release that touches nodes, subscriptions or money).
  - **Panel crash**: `serverErr` recursed on a nil error and took the process down on any `/sub` fetch that hit it.
  - **Privilege boundaries**: user writes (`PATCH /api/admin/users/{id}`, balance, token rotation) refuse staff accounts, so an operator can no longer make themselves an admin; failed-login throttling counts the TOTP step; `support` no longer sees subscription tokens, sub links or the connection log; `operator` no longer reaches the audit rules or the audit log; API tokens gain a scope (read-only) and an optional expiry, cannot manage staff accounts at all, and `/mcp` is behind the console allow-list.
  - **Money**: cancelling a queued plan now reverses its commissions and releases the coupon use (it only refunded the buyer before); commission payouts are recorded so a reversal cannot go negative.
  - **Node trust**: reports carry a batch number (bosun ≥ 0.46) and are applied exactly once, per-user deltas over 1 PiB are dropped, node timestamps are clamped to a plausible range, audit hits are checked against the rules the panel actually issued (and only `block` hits count toward the auto-ban, never for staff), Telegram text from a node is escaped and sent asynchronously, and every request body is capped (16 MiB for `/api/agent/`, 1 MiB elsewhere, 16 KiB of headers).
  - **Dynamic speed limit**: the rate is spread over the window each report says it covers, so a backlog after a restart no longer looks like one huge burst; users with no speed limit at all are left alone unless "throttle users without a speed limit" is on, because only they would need a core restart.
  - **Temporary links**: a use is spent when a document is actually served, not when the link is resolved, so a request a response rule refuses no longer burns one.
  - **Subscription endpoint**: 60 fetches per token and 600 per address in five minutes, client-supplied strings clipped before they are stored, at most 64 devices kept per user (oldest dropped), devices unseen for 90 days forgotten and the fetch history trimmed to 200 rows per user; 4xx request logs no longer print the token.
  - **Settings**: a PUT edits the keys it carries instead of replacing the whole document (a partial call no longer clears HWID, single-plan or the info lines), and a failed settings read keeps the cached value instead of caching "switched off" for 15 seconds.
  - **Housekeeping**: the connection log also keeps at most 1000 rows per user (Settings → Connection log, "Rows per user"), so one busy account cannot fill the database inside the retention window; connection log and audit log are pruned in batches and hourly even without the probe; deleting a user or a node takes its connection log, audit hits, throttles, devices and fetch history with it; migration 00045 cleans up orphans from before and backfills `first_connected_at` from the traffic history.
  - **Alerts**: after a panel restart every node gets one grace period to beat again before it counts as offline, and a fleet-wide batch is cut to Telegram's 4096-character limit.
  - **Port conflicts**: the inbound side and the forward side now share one model of what a node binds (per protocol, per listen address, disabled inbounds excluded), so tcp/443 and hysteria2 on udp/443 coexist and a mieru BOTH inbound reserves `port+1`.
  - Optional `min_version` in config.yaml refuses a self-update or rollback below that release; two labels that rendered as raw i18n keys fixed, 15 dead keys removed and the i18n check now fails on a key the sources use but no locale defines; bundled Caddyfile overwrites `X-Real-IP`; docs corrected (hysteria reports audit hits but cannot block, the role matrix, client-address handling, the dynamic limit's restart semantics, v0.55.0 was never tagged).
